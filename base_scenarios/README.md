# base_scenarios — Structural scenarios (no Traffic Profiles)

This directory holds **45 structural base scenarios** (families 01–06) used to define mobility, maps, node populations, and network configuration **before** applying Traffic Profiles (TP01–TP12).

## What is included

- One `.settings` file per **scenario base** (no `__TP` suffix in filename or `Scenario.name`).
- Families **01_urban … 06_social** only (45 bases in current benchmark split).
- Updated **map policy** (family-fixed WKT maps, rescaled `MovementModel.worldSize`).
- Original **Events*** blocks from the mobility design (not the TP overlay used in `corpus_v1/`).

## What is NOT included

- Traffic Profile overlays (TP01–TP12).

## Relation to other corpora

| Directory | Role |
|-----------|------|
| `base_scenarios/` | Structural template (this folder) |
| `corpus_v1/` | Paper benchmark: bases × Traffic Profiles (540 scenarios, 6 families) |
| `_archive/legacy_corpus_v1_pre_rename/` | Pre-rename historical mobility corpus |

## Maintenance (from repo root)

Bases are version-controlled; a fresh clone does not need regeneration. After map or `worldSize` changes:

```bash
python3 scenarios/setup/calibrate_world_size_per_map.py --apply
python3 scenarios/setup/migrate_corpus_maps.py --world-size-only
python3 scenarios/setup/build_base_scenarios_manifest.py
python3 scenarios/setup/audit_world_size_settings.py
python3 scenarios/analysis/validate_base_scenarios.py
```

## Manifest

[`manifest.csv`](manifest.csv) columns: `family`, `scenario_base`, `settings_file`, `source_tp_template`, `n_hosts`, `map_profile`, `movement_models`, `world_size`, `Scenario.endTime`, `notes`.

## Paper wording

> The project distinguishes between structural base scenarios and benchmark scenarios. Base scenarios define mobility, map, node population and network configuration. The benchmark corpus is generated by applying predefined Traffic Profiles to those base scenarios.
